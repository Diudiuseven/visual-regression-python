# 判定语义与配置项

本服务完全在单个进程内运行：图像解码、像素比较、差异图标注、基准存储
都不依赖任何外部服务或磁盘文件（基准保存在进程内存中）。

## 1. 像素如何被判定为“变化”

对于每个不在忽略区域内的像素 `(x, y)`，取基准图与候选图的 RGB 三个通道，
逐通道计算绝对差值：

```
dr = |R_base - R_cand|, dg = ..., db = ...
```

只有当**至少一个通道**满足严格大于容忍度时，该像素才被标记为原始差异像素：

```
dr > pixel_tolerance  或  dg > pixel_tolerance  或  db > pixel_tolerance
```

注意是**严格大于**：差值恰好等于 `pixel_tolerance` 的像素不算变化。
这样逐通道差值不超过容忍度的轻微渲染差异（抗锯齿、压缩抖动等）在源头
就不会进入统计。

### 连通域噪声抑制 `min_cluster_size`

通过容忍度之后的像素，再按**四连通**（上下左右）聚成连通域。像素数
小于 `min_cluster_size` 的连通域被视为孤立渲染噪声并丢弃；成片差异
（改色区域、元素位移产生的条带）构成大连通域，不会被吞掉。

判定流程：

```
原始差异像素 → 四连通分域 → 丢弃小连通域 → 得到最终变化像素
```

## 2. 最终判定与变化面积比例

忽略区域之外的像素总数记为 `considered_pixels`。最终变化像素数记为
`changed_pixels`，变化占比：

```
ratio = changed_pixels / considered_pixels
```

判定同样使用**严格大于**：

```
changed（有差异） 当且仅当  ratio > change_ratio
```

即恰好等于阈值时判为无差异。`considered_pixels = 0`（整张图都被忽略）
时永远判为无差异。

## 3. 配置项一览

### CompareConfig（对比参数）

| 参数 | 类型 | 默认值 | 含义 |
|---|---|---|---|
| `pixel_tolerance` | int, 0–255 | `16` | 逐通道容忍度；通道绝对差 `>` 该值才算该通道不同 |
| `change_ratio` | float, 0.0–1.0 | `0.01` | 变化面积比例阈值；变化占比严格大于该值才判 CHANGED |
| `min_cluster_size` | int ≥ 1 | `1` | 小于该像素数的四连通差异域按噪声丢弃。默认 1 = 不过滤 |
| `alpha_threshold` | int, 0–255 | `1` | alpha 低于该值视为透明；透明像素合成到黑色底色后再比较 |
| `auto_register` | bool | `true` | 用例没有基准时，是否把首张候选图自动登记为 v1 |
| `matte` | (r,g,b) | `(0,0,0)` | 透明像素合成底色（当前固定黑色） |

非法取值（超范围、类型错误）会在对比开始前以 `invalid_input` 拒绝。

### ResourceLimits（资源上限）

| 参数 | 类型 | 默认值 | 含义 |
|---|---|---|---|
| `max_pixels` | int | `4096*2304`（约 944 万） | 解码后宽×高上限 |
| `max_width` | int | `8192` | 解码后宽度上限 |
| `max_height` | int | `8192` | 解码后高度上限 |
| `max_bytes` | int | `33554432`（32 MiB） | 编码后输入字节数上限 |
| `pixel_budget` | int | `64_000_000` | 单个批次累计解码像素总量上限 |

超限在解码前/解码后立即终止该单项，不会分配大图缓冲拖垮进程。

## 4. 忽略区域

每个区域为轴对齐矩形：

```json
{"x": 10, "y": 20, "width": 100, "height": 40}
```

- `x, y` 为左上角，必须为非负整数；
- `width, height` 必须为正整数；
- 矩形必须**完全落在图像范围内**（`x + width ≤ 图像宽`，
  `y + height ≤ 图像高`），恰好贴边合法。

任何一个区域非法，整次对比被拒绝，错误形如
`ignore_regions[2]: rectangle ... exceeds image bounds 1920x1080`，
带区域下标，绝不静默按整图放行。区域内的差异完全不计入
`changed_pixels`；差异标注图中忽略区域用蓝色半透明叠加并描边。

## 5. 差异标注图（确定性输出）

标注图为进程内生成的 PNG，颜色含义：

- **红色 `(255,0,0)`**：最终计入判定的变化像素；
- **橙色 `(210,150,0)`**：有原始差异但被噪声过滤丢弃的孤立像素；
- **暗化的候选图**：无差异区域（乘以 0.4，便于凸显变化）；
- **蓝色填充 + 1px 亮蓝边框**：忽略区域。

所有像素运算只用整数，PNG 以固定压缩级别、不写时间戳等元数据编码，
因此**同一对输入 + 同一配置重复对比，差异图逐字节一致**，判定结论
也完全一致。

## 6. 基准版本化与审批

- 用例的基准是只追加（append-only）的版本序列，从 v1 开始编号；
- 替换走审批流：`propose`（暂存候选）→ `approve`（在一个临界区内
  追加为新版本）或 `reject`（丢弃暂存）；
- 每次对比读取的都是某个**完整不可变版本**（版本对象持有完整图像
  字节，历史列表只追加），对比与替换并发时读不到半更新状态；
- 历史版本可按版本号回溯，也可指定版本号与历史基准对比。

## 7. 四种结果状态

批量接口中每个条目独立返回一种状态：

| 状态 | 含义 |
|---|---|
| `success` | 非对比动作成功（首次自动登记 / propose / approve / reject） |
| `no_diff` | 对比完成，未达到变化判定 |
| `diff` | 对比完成，判定发生视觉变化（附差异图下载地址） |
| `failed` | 该条目无法处理（附稳定 `error_code`，不影响其他条目） |

## 8. 可区分的错误码

| error_code | HTTP | 触发场景 |
|---|---|---|
| `invalid_input` | 400 | 空载荷、损坏/截断图像、参数非法、非 base64 |
| `unsupported_format` | 415 | 识别出图像但格式不支持（仅支持 PNG/JPEG） |
| `image_too_large` | 413 | 字节数 / 宽高 / 像素量 / 批次预算超限 |
| `dimension_mismatch` | 422 | 基准与候选尺寸不一致 |
| `invalid_ignore_region` | 422 | 忽略区域格式非法或越界（含 `region_index`） |
| `baseline_not_found` | 404 | 用例/版本不存在且未启用自动登记 |
| `pending_change_not_found` | 404 | 没有待审批的替换却调用 approve/reject |
